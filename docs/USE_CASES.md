# DATAGEN 使用场景与竞品差异分析

## 一、使用场景

### 场景 1：运营人员 — "我不会写代码，但我要看数据报告"

> 小王是电商运营，老板丢给他一份上个月的销售 CSV，让他分析"哪个区域卖得好、促销有没有用"。他不会 Pandas，也不会 Matplotlib，更不会用随机森林做特征重要性分析。

**使用方式**：打开浏览器 → 在 Web 界面输入"请分析 OnlineSalesData.csv，做数据清洗、区域对比、促销效果评估，生成图表和中文报告" → 点"开始分析" → 几分钟后拿到：

- `analysis_report.md` — 完整的中文分析报告，含表格、统计结论和业务建议
- `*.png` — 多张可视化图表（趋势图、柱状图、热力图、散点图）
- 报告中用机器学习（随机森林）量化了各因素对销售额的影响，告诉运营"客户数是关键驱动因素"

**解决的痛点**：从"我不会做数据分析"到"我有一份专业报告"，中间不再需要求数据分析师。

---

### 场景 2：数据分析师 — "基础分析太重复了，我要快速出原型"

> 张三是数据分析师，每周要处理 5-10 份不同业务方的数据需求。80% 的工作是写同样的模板代码：`pd.read_csv` → `describe()` → `plt.bar()` → 写总结。他想跳过这些重复劳动，直接在 AI 生成的分析基础上做深度挖掘。

**使用方式**：把 CSV 丢进 data/ 目录 → 用自然语言描述分析需求 → 系统自动完成清洗、统计、可视化、建模的全流程 → 分析师拿到生成的 Python 脚本和图表，直接在此基础上修改深挖。

**解决的痛点**：从"每次写 200 行模板代码"到"验证 Agent 生成的结果，专注业务洞察"。Agent 生成的 Python 脚本可以复用和修改。

---

### 场景 3：中小企业 — "我们请不起全职数据团队"

> 一家 30 人的贸易公司，每天有销售数据但没人分析。老板想知道"哪个月份卖得最好、哪个产品该加大库存"，但没有预算招数据分析师。

**使用方式**：定期把销售 CSV 更新到 data/ 目录 → 一键运行 → 自动产出带图表和结论的分析报告 → 直接用于管理决策。

**解决的痛点**：用几块钱的 API 费用，替代几万块的人力成本。虽然不是百分百替代专业分析师，但对中小企业来说从 0 到 1 的价值巨大。

---

### 场景 4：教育/培训 — "让学生看到 AI 是怎么协作的"

> 一位大学老师想给学生展示"AI Agent 协作"的概念。不是讲 PPT，而是让学生亲眼看到 9 个 Agent 各司其职地完成一个分析任务——谁负责假设、谁调度、谁写代码、谁审查、谁润色。

**使用方式**：课堂上运行一次分析 → 控制台实时输出每个 Agent 的工作内容 → 学生看到 Agent 之间的消息传递和路由决策 → 理解"多 Agent 系统"的实际运作方式。

**解决的痛点**：AI Agent 教学缺少可运行、可观察的案例。DATAGEN 的分工明确、日志完整，适合做教学演示。

---

### 场景 5：自动化报告流水线 — "每周一自动出上周的销售周报"

> 运维工程师想搭建一个自动化的数据分析流水线：每周一凌晨自动读取上周的销售 CSV → 生成分析报告 → 发到飞书/钉钉群。

**使用方式**：把 DATAGEN 部署到服务器 → 配置 cron 定时任务 → 每周自动运行 → 输出固定的报告格式 → 机器人推送到群。

**解决的痛点**：报表自动化不需要从头造轮子，DATAGEN 提供了从数据到报告的全链路能力。

---

## 二、与通用大模型（豆包/ChatGPT/DeepSeek 对话框）的差异

单看一次分析的结果，通用大模型也能输出不错的报告。真正拉开差距的是**使用模式**和**可扩展性**。

### 差异一：你说目标，而不是指挥每一步

用豆包分析数据，你得知道分析流程：

> "先帮我做描述性统计" → "现在做区域对比" → "再帮我出促销效果图" → "最后写个报告"

每一步都是你主动发起，对话是你驱动的。如果漏了某个分析维度，模型不会主动补充——你没想到的，它也不会做。

DATAGEN 你只需要说一句：**"分析这份数据，给我一份完整报告"**。process_agent 收到这句话后，自己制定分析计划：先清洗数据、再做描述性统计、再做趋势和对比、再建模、再出图、最后写报告。**任务分解和执行顺序是系统自己决定的**，不是靠你的连续追问驱动的。

这不是"对话更智能"，而是架构决定的——LangGraph 的状态机在驱动流程，不是用户的下一句话。

### 差异二：可以扩展的 Agent 编排框架，而不是一个功能有限的产品

豆包是一个产品，你用它提供好的能力——今天能做什么，明天还是能做什么。如果你想加一个"分析完自动发钉钉"的功能，你做不了，只能等字节的 PM 排需求。

DATAGEN 的每个 Agent 是一个可以替换、新增、改写的模块。配置层面改 `config.yaml` 换工具、`agent_models.yaml` 换模型、`AGENT.md` 改行为逻辑；代码层面在 `src/agents/` 下新建一个 `alarm_agent.py`，注册到 `AgentFactory`，workflow 里加一个节点，整个系统就多了一个能力。

几个在现有架构上一天能加出来的例子：

- `notify_agent` — 分析完成后把报告推送到飞书/钉钉/企业微信群
- `sql_agent` — 从 CSV 变成直连 MySQL/PostgreSQL 查询
- `schedule_agent` — 定时触发分析，比如每周一早 8 点自动跑上周数据
- `compare_agent` — 对比两个时间段的数据，输出变化趋势和异常点

这不是一个"数据分析工具"，这是一个**可以组装不同分析能力的 Agent 编排平台**。通用大模型只能满足"问一个问题得到一个回答"，DATAGEN 的架构能承载"从数据采集到报告推送"的整条链路。企业可以在此基础上按自己的业务需求定制 Agent 和流程，而不用担心被一个产品的功能边界卡住。

### 差异三：团队协作模式 vs 个人顾问模式

通用大模型像一个全科医生——什么都能看，但深度有限。

DATAGEN 像一个科室齐全的医院——code_agent 专做数据清洗和统计建模（它的 AGENT.md 只描述这一件事），visualization_agent 专做图表（它的工具集只有 `execute_code`），report_agent 只负责把分析结果整理成报告。**每个 Agent 的职责范围极窄**，system prompt 不用考虑"我该怎么出图"、"我该用什么统计方法"之外的事情，所以在这个窄领域里表现更稳定。

这种分工不是 prompt 层面的建议（"你是一个数据分析师，请做 A、B、C"），而是**架构层面的强制隔离**——code_agent 根本没有 `create_document` 工具，它想写报告也写不了；report_agent 没有 `execute_code`，想出图也出不了。每个 Agent 的职责边界不由 prompt 约束，由它能调用的工具集约束。这比"在 prompt 里说请扮演 X 角色"可靠得多。

---

### 直接对比

| 维度 | 通用大模型 | DATAGEN |
|------|-----------|---------|
| 交互模式 | 用户一步一步指挥："先做 A""再做 B" | 用户说目标，process_agent 自己拆任务、定顺序 |
| 扩展性 | 零——产品功能固定 | 加 Agent 类 + 注册 + 加节点，系统的能力边界你自己定 |
| 职责隔离 | 靠 prompt（不稳定） | 靠工具集限制（code_agent 根本调不了写报告的工具） |
| 模型选择 | 单一模型 | 每个 Agent 独立选模型，写代码和写报告可以用不同的模型 |
| 产出形式 | 文本回复 | 工作目录里的真实文件（`.md`、`.png`、`.py`） |

## 三、面试话术

> "通用大模型能生成分析思路和代码，但它停在'建议'层面——你得自己跑代码、出图、写报告。我的项目做了一个关键架构升级：把单模型变成多 Agent 协作系统。每个 Agent 有独立的角色定义、工具集和模型配置，通过 LangGraph 状态机做流程调度。它不是'一问一答'，而是'一个团队在干活'——有人写代码并执行、有人出图表、有人做质量审查、有人润色报告。最终产出的不是一段 Markdown 文本，而是工作目录里真实的分析报告、图表文件和可复用的 Python 脚本。"

---

## 四、架构示意

```
用户输入（一句话）
        ↓
  hypothesis_agent  → 读取数据，制定分析方向
        ↓
  process_agent     → 任务分解和 Agent 调度
        ↓
  ┌── code_agent       → 写 Python 脚本并真实执行
  ├── visualization_agent → 生成 Matplotlib 图表
  ├── search_agent     → 联网搜索补充信息
  └── report_agent     → 撰写分析报告章节
        ↓
  quality_review_agent → 审查质量，不合格打回重做
        ↓
  refiner_agent        → 润色整合，输出最终报告
        ↓
  产出：report.md + *.png + *.py（真实文件）
```
